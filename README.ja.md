# LiTime BMS Logger

*[English README](README.md)*

LiTime BMS Logger は、LiTime の Bluetooth BMS バッテリーから BLE 経由でテレメトリを読み取り、リアルタイム表示・ローカルへのログ保存・CSV エクスポートを行う Android 向け React Native アプリです。

**本アプリは LiTime 公式のアプリではありません。**

## 対応デバイス

LiTime の Bluetooth BMS 搭載バッテリー。以下のいずれかに該当するデバイス名をアドバタイズしている場合に認識します。

- `LT-` で始まる
- `L-` に続いて数字が来る(例: `L-24050BNNA70-XXXXXX`)
- `LiTime` を含む

`L-24050BNNA70`(24 V・8直・50 Ah)で動作確認済みです。

## 必要環境

- Node.js 18 以上
- React Native の Android 開発環境
- Android Studio / Android SDK
- BLE 対応の Android 端末

## Android のパーミッション

Android 12 / API 31 以降では、スキャンと接続に実行時 Bluetooth パーミッションが必要です。

- `BLUETOOTH_SCAN`
- `BLUETOOTH_CONNECT`

Android 11 / API 30 以前は従来のパーミッションを使用します。

- `BLUETOOTH`
- `BLUETOOTH_ADMIN`
- `ACCESS_FINE_LOCATION`

マニフェストは Android 現行の Bluetooth パーミッションモデルに従っています。Android 12 で `BLUETOOTH_SCAN`・`BLUETOOTH_ADVERTISE`・`BLUETOOTH_CONNECT` が導入され、従来の Bluetooth パーミッションは `android:maxSdkVersion="30"` を付けて Android 11 以前に限定すべきとされています。公式ドキュメント: https://developer.android.com/develop/connectivity/bluetooth/bt-permissions

## BLE UUID

- Service: `0000ffe0-0000-1000-8000-00805f9b34fb`
- Notify: `0000ffe1-0000-1000-8000-00805f9b34fb`
- Write: `0000ffe2-0000-1000-8000-00805f9b34fb`

コマンドは `00 00 04 01 <CMD> 55 AA <CMD + 0x04>` の形式です。接続中は以下のステータスクエリを1秒間隔で送信します。

```text
00 00 04 01 13 55 AA 17
```

## プロトコル

BMS は notify キャラクタリスティック経由で105バイトの `0x93` フレームを返します。**マルチバイト値はすべてリトルエンディアンです。**

| オフセット | 型 | 内容 |
| --- | --- | --- |
| 0-1 | — | ヘッダ `00 00` |
| 2 | u8 | ペイロード長(`0x65` = 101)。フレーム長 = ペイロード長 + 4 |
| 4 | u8 | 応答コード `0x93`(クエリ `0x13` の最上位ビットを立てた値) |
| 8-11 | u32 | 未文書。電圧ではない — 後述 |
| 12-15 | u32 | 総電圧(mV)。セル電圧の合計と一致 |
| 16-47 | u16 × 16 | セル電圧(mV)。未使用スロットは 0 |
| 48-51 | i32 | 電流(mA)。負値 = 放電 |
| 52-53 | i16 | セル温度(℃) |
| 54-55 | i16 | MOSFET 温度(℃) |
| 62-63 | u16 | 残容量(0.01 Ah 単位) |
| 64-65 | u16 | 満充電容量(0.01 Ah 単位) |
| 68-71 | u32 | ヒーター状態(bit `0x80` = 放電禁止) |
| 76-79 | u32 | 保護フラグ |
| 80-83 | u32 | 故障フラグ(表示しない — 後述) |
| 84-87 | u32 | バランシング状態(セルごと1バイト) |
| 88-89 | u16 | バッテリー状態(`0` 放電中・`1` 充電中・`4` 充電禁止) |
| 90-91 | u16 | SOC(%) |
| 92-93 | u16 | SOH(%) |
| 96-99 | u32 | 放電サイクル数 |
| 100-103 | u32 | 積算放電量(mAh) |
| 104 | u8 | チェックサム: バイト 0〜103 の総和 mod 256 |

### 保護フラグ(オフセット76)

| ビット | 意味 |
| --- | --- |
| `0x00000004` | セル過充電 |
| `0x00000020` | セル過放電 |
| `0x00000040` | 充電過電流 |
| `0x00000080` | 放電過電流 |
| `0x00000100` | 高温警告 1 |
| `0x00000200` | 高温警告 2 |
| `0x00000400` | 低温警告 1 |
| `0x00000800` | 低温警告 2 |
| `0x00004000` | 短絡検出 |

この表にないビットは、破棄せず生の16進数として報告します。異常がない場合 `protectionStatus` は未設定のままになります。オフセット80 の故障ワードは表示しません(「未確定の項目」参照)。

### フレームの検証

フレームはヘッダ・長さフィールド・応答コード・チェックサムがすべて整合した場合のみ受理します。デコード後にはセル電圧の合計を総電圧と照合し、0.05 V を超えてずれていればフレームを棄却します。いずれかのチェックに失敗したフレームは生の16進文字列としてのみ保存されるため、プロトコルが変更された場合でも**誤った値を表示するのではなく、ログ保存のみに縮退します**。

### 未確定の項目

- **電流(オフセット48)** — バッテリーの状態が変化したキャプチャを含め、これまで採取した全フレームで 0 でした。このオフセットが本当に電流であることを確定するには、既知の充電または負荷をかけた状態でのキャプチャが必要です。
- **バイト 8-11** — 資料に記載がなく、**電圧ではありません**。あるセッションでは総電圧より約 20 mV 高い値を示していましたが、別のセッションではパック電圧が 26294 mV・SOC も不変のまま 5124 を示しました。本アプリはこの値を使わず、他の LiTime 系ツールに合わせてオフセット12 を総電圧として扱います。
- **故障フラグ(オフセット80)** — **本アプリでは表示しません。** 電圧を保持し、保護ビットも立たず、容量にも変化のない健全なパックで `0x00020001` を示しました。異常ではなく、オフセット68 のヒーター状態バイトと連動して変化しています。ビットごとの意味も公開されておらず、これで警報を出してもオオカミ少年になるだけです。生フレームは常に記録されるため、値は後から解析できます。
- **ヒーター状態(オフセット68)** — パック温度の上昇に伴い `0x00` から `0xc0` へ変化するのを観測しました。資料にある `0x80`(放電禁止)に未文書の `0x40` が加わったものと整合します。未デコードです。

## 取得できる項目

表示およびログ保存の対象:

- 総電圧
- 電流
- SOC
- 残容量(Ah)
- 満充電容量(Ah)
- セル電圧
- バッテリー温度
- MOS 温度
- 保護ステータス
- 充放電ステータス
- SOH
- サイクル数
- 生レスポンス(16進)

## 開発

依存関係のインストール:

```sh
npm install
```

Android での実行:

```sh
npm run android
```

型チェック:

```sh
npm run typecheck
```

## CSV エクスポート

保存したログは以下の形式で書き出せます。

```text
litime_bms_log_YYYYMMDD_HHMMSS.csv
```

Android では、利用可能な場合は公開ダウンロードディレクトリに書き込まれます。

## 補足

- BLE エラーはアプリをクラッシュさせず、UI 上に表示されます。
- デバイスに接続してテレメトリを受信するまで、ログ記録は開始できません。
- BLE notify の生データは、今後のプロトコル検証のため16進文字列で保存されます。
- 初回の接続試行は Android GATT の `status=133` で失敗することがよくあります。クライアントは2秒後に自動でリトライし、通常は数回の試行で接続に成功します。
- iOS は未実装ですが、BLE・パーサー・データベース・UI の責務を `src/` 配下で分離しており、移植しやすい構成を保っています。
